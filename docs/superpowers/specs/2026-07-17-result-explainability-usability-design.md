# 关键帧结果解释与易用性优化设计

## 背景与目标

当前 macOS App 已能完成视频人物关键帧提取，但结果评分缺少解释、预览无法检查细节、数值参数只能逐次点击，且主界面的“预处理”选项容易让用户误以为输出图片会改变比例。

本次改动让用户能够理解为什么某帧得分较高、放大检查原始画面细节，并高效输入长视频所需的关键帧数量，同时不改变现有检测算法和输出图片内容。

## 方案比较

### 方案 A：透传真实评分分项并做针对性交互增强（采用）

- 核心评分器返回人物大小、检测置信度、居中程度、稳定性四项原始分数及加权贡献。
- 结果卡片显示两项最有代表性的简短理由，预览页显示完整公式和分项明细。
- 使用原生 SwiftUI 手势和控件增加缩放、平移及数字输入。
- 主界面移除“预处理”，底层继续使用当前已验证配置。

优点是解释与真实算法完全一致、改动边界清晰、不引入外部依赖。缺点是需要扩展核心结果模型，并同步 CLI 编码结构。

### 方案 B：只在界面根据最终分数生成文案（不采用）

无需修改核心模型，但只能给出推测性解释，无法证明各项因素对最终得分的真实贡献，会削弱用户信任。

### 方案 C：重新设计评分算法并加入人物追踪（本期不采用）

可以让稳定性更准确，但会改变现有结果排序并显著扩大验证范围。本次只解释现有算法，不调整权重和检测逻辑。

## 功能设计

### 1. 可解释评分

新增评分明细结构，包含：

- 人物大小分：原始值 `0...1`，权重 40%。
- 人物检测置信度：原始值 `0...1`，权重 30%。
- 居中程度：原始值 `0...1`，权重 20%。
- 画面稳定性：原始值 `0...1`，权重 10%。
- 综合分：四项加权贡献之和，必须与当前 `score` 一致。

结果卡片继续展示综合评分，并将“置信”改为“人物检测置信度”。卡片新增一行简短理由，从四个原始分项中选择数值最高的两项，显示类似“人物突出 · 居中良好”的文案；文案仅用于快速阅读，不替代数值明细。

预览窗口展示完整明细，每项同时给出原始分、权重和实际贡献。例如：`人物大小 0.92 × 40% = 0.368`。稳定性没有轨迹信息时明确显示为低分，不虚构检测依据。

### 2. 可缩放预览

预览图片保持原始宽高比，不裁切、不拉伸。支持：

- 触控板捏合缩放。
- 鼠标拖动查看放大后的不同区域。
- `-`、当前倍率、`+` 和“还原”控件。
- 缩放范围 `1x...8x`；切换关键帧或关闭预览后恢复为 `1x`。

图片在 `1x` 时完整适配可用区域；只有倍率大于 `1x` 时允许平移，并限制偏移量，避免图片完全拖出可视区域。

### 3. 数字直接输入

采样率和最大关键帧均采用“数字输入框 + 上下步进按钮”的组合：

- 采样率范围保持 `1...20`，仅接受整数。
- 最大关键帧范围扩大为 `1...500`，支持直接输入 `200` 等长视频需求。
- 输入为空或编辑中出现非法字符时暂不触发处理；提交或失焦时将值修正到合法范围。
- 处理任务启动时再次执行相同范围校验，避免绕过界面约束。

置信度滑杆保持不变。

### 4. 移除主界面预处理选项

从参数区移除“预处理”“拉伸”“留边”的控件及帮助入口。底层检测配置、诊断导出和 CLI 参数保持不变，App 继续使用当前默认检测配置。

该设置只影响送入 Core ML 的检测画面，现有预览和导出仍使用采样得到的视频原始帧。本次不修改输出图片、不改变宽高比，也不删除底层预处理能力。

## 代码边界与数据流

1. `KeyframeScorer` 负责计算并返回真实评分分项，避免界面重复实现公式。
2. `LocalProcessingService` 将评分分项连同原始帧图片映射到 `KeyframePreview`。
3. `KeyframePreview` 提供界面所需的分项数据和简短理由，不参与重新评分。
4. `ResultView` 只负责卡片呈现；可缩放预览拆成独立 SwiftUI 视图，隔离手势状态。
5. `SidebarView` 使用可复用整数输入控件，`AppModel` 在启动处理前执行最终参数归一化。

## 兼容性与错误处理

- 已存在的 `ScoredKeyframe` JSON 增加评分明细字段；当前应用和 CLI 同仓升级，不读取旧任务缓存，因此不设计迁移层。
- 图片加载失败仍沿用现有占位和失败状态，不因缩放功能改变处理结果。
- 数字输入不会产生负数、零值或超过上限的任务配置。
- 中英文界面同步新增评分原因、分项、缩放和还原文案。

## 验收标准

1. 同一检测结果在改动前后的综合分和排序一致。
2. 每张结果卡片展示综合评分、完整命名的检测置信度和两项简短理由。
3. 预览窗口可在 `1x...8x` 之间缩放，放大后可拖动，点击还原回到 `1x`。
4. 采样率可直接输入 `1...20`；最大关键帧可直接输入并成功处理 `200`，最大允许 `500`。
5. 主界面不再显示预处理选项，预览和导出图片宽高比与原始视频帧一致。
6. 核心评分单元测试、Swift 包全量测试及 App 构建均通过。

## 测试策略

- 先为评分明细和综合分一致性补充失败测试，再扩展核心模型。
- 为简短理由选择规则和参数范围归一化提取可测试的纯逻辑。
- 运行 `swift test` 验证全部核心逻辑。
- 运行 App 构建脚本验证 SwiftUI 编译和资源打包。
- 使用样本视频手工验收评分文案、数字输入、缩放平移以及原图比例。
